# The intention of this project

Static PHP Builds publishes precompiled PHP for `mise`, thus a developer installs PHP with a download and not with a compile. Each GitHub release holds the PHP CLI with the extensions that Laravel needs, Composer and Xdebug, for Linux x86_64, Linux aarch64 and macOS arm64. It is an application: a set of Bash scripts and GitHub Actions workflows that build, test, attest and publish each release. No developer installs this repository as a package.

The project has no dependency manager and no install command: the scripts need `bash`, `curl`, `tar`, `jq`, `git` and, on CI, `gh`. Run the lint checks with `shellcheck --external-sources bin/build scripts/*.sh stubs/php stubs/composer`, as `.github/workflows/ci.yml` does. Build and smoke test one branch on this machine with `bin/build <branch>`. Build one version with `scripts/build.sh <version> <php-source-sha256> <platform> <source-url>`, then test the tarball with `scripts/smoke-test.sh dist/php-<version>-<platform>.tar.gz <version> <platform>`. Update every pinned version and checksum in `config/build.env` and `.github/workflows/ci.yml` with `scripts/update-pins.sh`. Refresh `config/sources.lock` with `gh workflow run release.yml -f version=<branch>`: the build stops at the lock check and uploads the changed lines as `sources.drift` in the `build-logs-*` artifact, and you replace the lines in the lock after you review each upstream change. Add a new PHP branch with its line in `config/php-branches.txt` and the release manager keys of that branch, from `https://www.php.net/gpg-keys.php` and `https://www.php.net/distributions/php-keyring.gpg`, in `config/php-release-keys.txt` and `config/php-release-keys.asc`. Dependabot updates the GitHub Actions and `zizmor` with a pull request.

- `bin/` — `build`, the command that builds and smoke tests one PHP branch on this machine
- `.github/` — the workflows: `ci.yml` lints, `release.yml` plans, builds, smoke tests and publishes each release when a user starts it, `updates.yml` compares the pinned tools with upstream each day and keeps one issue open while a tool is behind
- `config/` — the pinned versions and checksums in `build.env`, the PHP extensions in `extensions.txt`, the PHP branches in `php-branches.txt`, the checksum or commit of every other build source in `sources.lock` and the PHP release manager keys in `php-release-keys.asc` with their branches in `php-release-keys.txt`
- `patches/` — the patches that `scripts/build.sh` applies to a source before the build
- `scripts/` — the Bash scripts that resolve a PHP version, plan the releases, build, smoke test and publish
- `stubs/` — the files that go into each release: the `php` and `composer` wrappers and `xdebug.ini`
